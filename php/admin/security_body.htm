Security Scanner
Scans this site's page code (the controller, functions and body of every _pages record, and every _templates record) for places where request data, such as $_REQUEST, $PASSTHRU or cookies, reaches SQL, HTML output, or code and file execution without validation or escaping. The scan only reads code; it changes nothing. Results show what to fix, plus a "Fix with AI" prompt you can hand to an assistant.
What gets flagged, and what doesn't
SQL injection: request data inside SQL text, or in a -where, -filter, -order, -query, -fields, -group, -having, -limit, -offset or -search value. Plain filter keys such as 'name'=>$_REQUEST['name'] are not flagged, because WaSQL escapes those itself.
Cross-site scripting: request data written into the page through <?=...?>, echo, or an HTML string, without encodeHtml(), htmlspecialchars() or a numeric cast.
Code / file execution: request data reaching eval, include/require, shell functions, unserialize, file reads/writes, or extract. Page inclusion: request data choosing includePage() or loadDBFunctions(). Open redirect: request data in a Location: header.
Low findings are worth a look but often fine: the value is validated (isNum, in_array, preg_match, switch...) somewhere on the same page, so check that the validation covers the flagged line.
The scan is heuristic. Expect some false positives, and it can't follow code across pages (functions_common) or catch stored XSS from database values.
